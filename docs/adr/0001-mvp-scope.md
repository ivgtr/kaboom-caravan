# ADR 0001: MVPの実装境界

- Status: Accepted
- Date: 2026-08-10

## 決定

最初のプレイ可能版は、固定順の約10戦、戦闘後3択報酬、最終ボスという直線的なランにする。

以下をMVPのコアへ含める。

- 横方向の移動、距離管理、前線の押し引きとリスク・報酬
- 主武器、副武器、特殊能力の入力境界
- 熱、電力、弾薬、耐久力
- 5種類以上の敵、6種類以上の武器、10種類以上のパーツ
- Wave、報酬、Trigger / Modifier、Seed付きRNG
- ボス、勝利、敗北、ランリセット

以下はコア戦闘のプレイテスト後まで保留する。

- 分岐ルート、ショップ、イベント
- キャラバン支援車両
- 複数エリア、複雑な永続進行
- タッチ、ゲームパッドへの具体的UI
- 途中ランの保存・再開

MVPの詳細な実装順序と完了条件は[実装計画書](../実装計画書.md)で管理する。

## 実装上の仮決定

- Simulationは60Hz固定ステップとする。
- 戦闘座標は自陣を0、敵陣を100とする。
- MVP初期実装ではプレイヤー位置を0〜80に制限する。
- キーボードの仮操作は、移動を`A/D`または左右キー、主武器を`Space`とする。
- UI Snapshotは最大10Hz程度とし、敵位置などの描画状態をReactへ渡さない。
- プレースホルダ形状でコア戦闘を検証しつつ、G0アセットだけを早期に実画面へ投入する。

これらの数値と入力はバランス仕様ではなく、層間接続を検証するための初期値である。

## 未決定事項

次の項目はプレイテスト可能な縦切りを作った後に決める。

- 前線位置と報酬倍率の計算式
- 戦闘ごとの勝利・敗北条件と所要時間
- 武器・モジュールのスロット数、重複装備可否
- 熱、電力、弾薬の基準値と回復規則
- 報酬抽選、レアリティ、救済処理
- 特殊能力の内容
- 対象ブラウザ、最低端末性能、解像度、FPS予算
- Save保存先、バージョニング、マイグレーション
- 生成アセットの利用サービス、ライセンス記録、Git LFS運用

## 整合性対応

要件書はパーツ10種類以上、アート側のMVP一覧は8モデルを定義している。ゲーム上のパーツ数は10以上を満たし、追加2種類が既存モデルを共有できるかはG0検証後に決める。

ゲーム内ID、表示名、アセットIDの対応表は、最初の武器データを追加するときに単一Registryとして作成する。
