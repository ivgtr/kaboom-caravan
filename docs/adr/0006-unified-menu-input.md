# ADR 0006: 戦闘・メニュー共通の入力基盤

- Status: Accepted
- Date: 2026-08-11

## 決定

物理キーの割り当ては `InputManager` へ集約し、入力コンテキストを `combat` と `menu` の2種類に限定する。

### 戦闘

押下中の状態を固定更新ループから読み取る。

- `A` / `←`: 後退
- `D` / `→`: 前進
- `Space`: 主武器
- `C`: 副武器
- `F`: 迎撃パリィ
- 左`Shift`: 入力中の方向へ急加速

迎撃パリィと急加速はどちらも押下中の状態を固定更新ループから読み取る。急加速は方向入力と左`Shift`の両方を保持している間だけ有効になる。両方が同じ固定更新へ入った場合は迎撃パリィを優先する。

### メニュー

キーを押した瞬間に意味アクションを通知する。

- `A` / `←`: 前の項目
- `D` / `→`: 次の項目
- `Space` / `Enter`: 決定
- `Escape`: 戻る
- `1`〜`3`: 画面固有の直接選択

前後移動だけはOSキーリピートを許可し、決定・戻る・直接選択はリピートしない。入力欄への文字入力と、フォーカス中の通常ボタンが持つSpace / Enter操作は横取りしない。

## UI実装

整備庫、進路選択、戦利品、武器装着先、勝敗結果は共通の `useMenuNavigation` を使用する。

- 選択位置とDOMフォーカスを常に同期する
- マウスで指した項目を次のキーボード操作の起点にする
- 未解禁・無効項目は移動時に飛ばす
- 端から反対端へ循環する
- 画面表示時に最初の有効項目へフォーカスする
- 装着先のような子メニュー表示中は親メニューを無効化する
- 画面遷移時に押下状態を消去する

各画面が `window.keydown` を直接監視する実装は持たない。

## 理由

戦闘と画面ごとのキー処理が分散すると、同じキーの意味、キーリピート、フォーカス、画面遷移時のリセットが別々に実装される。物理入力を一か所へ集約し、画面側は項目数と決定処理だけを渡すことで、操作感と不具合対策を共通化できる。

選択状態とDOMフォーカスを別々に持つと、マウスが示す項目とキーボードで決定される項目が食い違う。共通hookを唯一の選択状態とし、実ボタンへフォーカスを移すことで、ゲーム操作とブラウザ標準のアクセシビリティを両立する。
