# ローグライク装甲車キャラバン
# グラフィック生成指示書

Version: 1.0

---

# 1. 本書の目的

本書は、画像生成AI・3D生成AI・生成エージェントを用いて本ゲームのグラフィックアセットを継続的に生成するための実務仕様書である。

世界観そのものについては別途「グラフィック・世界観設計書」を正とし、本書では以下に限定して定義する。

- 出力サイズ
- アスペクト比
- カメラ
- オブジェクト縮尺
- デフォルメ率
- 配色
- プロンプト構造
- Reference運用
- 生成順序
- Negative条件
- 再生成条件
- 3D化条件
- ファイル命名
- 品質判定

目標は、

> **別々のタイミングで生成したアセットを並べても、同じゲームのために同じアートチームが制作したように見えること**

である。

---

# 2. 最重要原則

生成時には毎回自由なプロンプトを書かない。

すべての生成は以下の構造を使用する。

```text
[STYLE LOCK]
+
[ASSET CLASS LOCK]
+
[CAMERA LOCK]
+
[COMPOSITION LOCK]
+
[ASSET DESCRIPTION]
+
[COLOR SPEC]
+
[OUTPUT CONTRACT]
+
[NEGATIVE CONSTRAINTS]
```

原則として変更してよいのは、

```text
[ASSET DESCRIPTION]
[COLOR SPECの一部]
```

のみ。

それ以外は全アセットで固定する。

---

# 3. 生成工程

全アセットは以下の工程を基本とする。

```text
世界観確定
↓
Style Reference生成
↓
Player Vehicle基準デザイン生成
↓
Player Vehicle 3D化
↓
基準Enemy生成
↓
実ゲーム画面で確認
↓
STYLE LOCK確定
↓
Weapon / Module / Enemy量産
↓
Environment量産
↓
UI / Icon
↓
VFX
```

量産開始前に必ず、

- Player
- Basic Enemy
- Machine Cannon
- Environment

の4系統を実ゲーム上で並べる。

これらが成立するまで他アセットを大量生成しない。

---

# 4. 生成形式

生成物を以下の5種類へ分類する。

| Class | 用途 |
|---|---|
| CONCEPT | デザイン確定 |
| MODEL_REF | 3D生成用参照 |
| MODEL | 3Dモデル |
| ICON | UI |
| VFX_REF | VFX制作参照 |

同じプロンプトを全Classへ流用しない。

# 5. 基準画像サイズ

## 5.1 Concept Hero

用途：

- デザイン検討
- Style Reference
- 3D生成のPrimary Reference

推奨：

```text
Aspect Ratio: 1:1
Target Resolution: 2048 × 2048
Minimum Acceptable: 1024 × 1024
```

オブジェクト占有率：

```text
Canvas Widthの70〜78%
Canvas Heightの55〜72%
```

四辺には最低10%程度の余白を残す。

# 6. MODEL_REF画像

3D生成用Referenceは以下を個別生成する。

### Primary

```text
three-quarter front side
2048 × 2048
```

### Secondary Side

```text
exact side-oriented view
2048 × 2048
```

### Secondary Front

```text
front-oriented view
2048 × 2048
```

### Optional Rear

```text
rear-oriented view
2048 × 2048
```

**4方向を1枚のReference Sheetへまとめない。**

3D生成器が複数画像入力に対応する場合は、

```text
Primary 3/4
+
Side
+
Front
```

の3枚を基本入力とする。

# 7. 背景画像

ゲーム背景コンセプト：

```text
Aspect Ratio: 16:9
Target Resolution: 2560 × 1440
```

横長背景素材：

```text
Aspect Ratio: 2:1
Target Resolution: 3072 × 1536
```

ゲームで直接背景Textureとして使用する場合は、採用後に用途に合わせて最適化する。

# 8. UIアイコン

Master生成：

```text

1:1
```

実際のゲーム利用時：

```text

```

を派生生成する。

AIに最初から32×32を直接描かせない。

# 9. VFX Reference

```text
Aspect Ratio: 1:1

```

アニメーション段階を生成する場合でも、

**1画像に大量のフレームを並べることを基本としない。**

```text

```

を個別に生成する。

rounded chunky proportions

# 12. デフォルメ比率

全Vehicleで以下を基準とする。

現実形状に対して、

```text
Wheel diameter:
1.15〜1.35倍

Weapon barrel thickness:
1.4〜2.0倍

Weapon muzzle:
1.5〜2.5倍

Mechanical button / bolt / joint:
1.5〜2.0倍

Cabin vertical dimension:
1.05〜1.15倍

Vehicle longitudinal length:
0.80〜0.92倍
```

つまり、

> **短く、太く、大きい**

を基本とする。

極端なChibi化はしない。

| Enemy | 長さ |
|---|---:|
| Basic | 0.55 |
| Rusher | 0.42 |

# 15. Weaponサイズ

武器の存在感を非常に強くする。

Player Vehicleの長さを4.8mとして、

| Weapon | 長さ目安 |
|---|---:|
| Machine Cannon | 1.4m |
| Scatter Cannon | 1.1m |
| Flamethrower | 1.2m |
| Rocket Launcher | 1.2m |
| Railgun | 2.4m |
| Mine Launcher | 0.9m |

Railgunのみ車体に対して明らかに過剰な大きさを許容する。

# 16. Moduleサイズ

Moduleはゲーム中カメラから識別できるサイズにする。

最小寸法：

```text
Player Vehicle Lengthの約12%
```

を目安とする。

小さな現実的部品にしない。

例えば冷却ファンであれば、

```text
直径 0.55〜0.8m
```

程度まで誇張する。

---

# 17. Camera Lock — Vehicle

全Vehicle Referenceで以下を基本とする。

Primary：

```text
three-quarter front-side view
camera yaw approximately 35 degrees from perfect side
camera pitch approximately 10 degrees downward
vehicle horizontal
camera centered at body mid-height
minimal perspective distortion
```

レンズ感：

```text
70〜100mm equivalent
```

広角表現は禁止する。

目的：

- 車体比率が歪まない
- 武器サイズが比較しやすい
- Image-to-3Dへ渡しやすい

---

# 18. Camera Lock — Weapon / Module

```text
three-quarter front view
yaw 30〜40 degrees
pitch 10〜15 degrees downward
minimal perspective distortion
object centered
```

接写的な広角レンズ表現は禁止。

---

# 19. Camera Lock — Icon

IconはPerspectiveを最小限にする。

```text
three-quarter iconographic view
centered
no dramatic perspective
```

---

# 20. 背景Lock

CONCEPT / MODEL_REFでは背景を統一する。

```text
plain warm light gray studio background
RGB impression around #F2F0EC
soft ground contact shadow
no scenery
no decorative objects
```

真っ白は避ける。

透明背景を直接要求すると輪郭が不安定になるモデルの場合、後処理で切り抜く。

---

# 21. ライティングLock

MODEL_REF：

```text
soft neutral studio lighting
large soft key light from upper-left
very soft fill light
subtle contact shadow
no dramatic rim lighting
no colored lighting
no sunset lighting
```

Lightingによってデザインを良く見せない。

形状そのものを確認できることを優先する。

# 23. Enemy Palette Rule

Enemyも世界観を維持するため暗色一辺倒にはしない。

ただしPlayerとの差別化として、

```text
Player:
warm / friendly palette

Enemy:
slightly cooler or more saturated accent palette
```

を利用する。

敵の種類は色ではなく形で区別する。

---

# 24. MATERIAL LOCK

3D素材表現：

```text
painted stylized metal
matte rubber
simple tinted glass
occasional emissive accent
```

禁止：

```text
mirror chrome
realistic brushed metal everywhere
mud layer
complex rust masks
photoreal paint scratches
realistic carbon fiber
```

---

# 25. Surface Detail Density

モデルを画面上で幅150〜350px程度で表示しても識別できる必要がある。

そのため、

```text
1面に意味のあるDetail:
最大3〜5個程度
```

を目安とする。

大量の、

- Rivet
- Cable
- Bolt
- Panel line

を生成しない。

# 30. Multi-view生成方法

同じVehicleのSecondary Viewを生成する場合、プロンプト全文を書き換えない。

Primary画像をReferenceとして入力し、

変更するのはCamera指定のみ。

Side：

```text
Preserve exactly the same vehicle design,
proportions, colors, wheel count,
armor shapes and attachment areas as the reference image.

Change only the camera.

Camera:
clean direct left-side-oriented view,
very weak perspective,
vehicle perfectly horizontal.
```

Front：

```text
Preserve exactly the same vehicle design.

Change only the camera.

Camera:
clean front-oriented view,
camera centered,
vehicle symmetrical unless the reference explicitly contains intentional asymmetry.
```

Rearも同様。

---

# 31. Multi-viewの禁止事項

Secondary生成時には、

```text
redesign
variation
alternative
inspired by
reinterpret
```

などの語を使用しない。

これらは形状変更を誘発する。

必ず、

```text
preserve exactly
change only the camera
```

を使用する。

---

# 32. Reference強度

生成器にReference Strength等が存在する場合、

### デザイン固定後

高めに設定する。

目的は創造性ではなく一貫性。

### 初期Concept探索

中程度にする。

量産フェーズでReference強度を下げて多様性を得ようとしない。

多様性はASSET DESCRIPTIONで作る。

---

# 33. Seed

生成器がSeed固定に対応する場合：

### 同一AssetのView生成

同一Seedを優先。

### 別Asset

Seedは変更してよい。

ただし、

Style ReferenceとReference Imageを必ず維持する。

Seedだけで世界観統一を行わない。

# 45. Background生成ルール

背景にはPlayerやEnemyと同じDetail Densityを使わない。

背景は必ず低情報量にする。

Promptへ追加：

```text
Background-detail rule:

large simple shapes,
low local contrast,
minimal small props,
no high-frequency texture,
no sharp high-contrast details near the gameplay lane.

The central horizontal gameplay area must remain visually quiet.
```

# 46. Gameplay Lane

# 63. Style Driftチェック

- Low-poly generic assetになった
- 子供向け玩具になった
- Chibiすぎる
- 細部がリアルすぎる

- 汚れが強すぎる

- 背景だけ写実的

# 76. 本書の最上位ルール

生成エンジンへ、

> 「この世界観でいい感じに作って」

とは依頼しない。

常に、

```text
固定Style
+
固定Camera
+
固定Scale
+
固定Composition
+
明示的なGameplay Role
+
変更可能なAsset固有情報
```

として依頼する。

また、量産段階では創造性より再現性を優先する。

本プロジェクトにおける生成AIの役割は、

> **毎回新しいデザインを発明すること**

ではなく、

> **確定済みのVisual Languageに従って、新しいゲームAssetを安定して追加すること**

である。
