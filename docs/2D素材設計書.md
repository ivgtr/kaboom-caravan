## 1. 目的

既存の[デザイン設計書](デザイン設計書.md)と[グラフィック指示書](グラフィック指示書.md)の世界観・配色・Shape Languageを維持しながら、MVPを3Dモデルなしの2D Raster素材で構成するための差分仕様を定める。本書と既存資料がMVPの描画方式について競合する場合、本書を優先する。

## 3. 透明素材

独立素材は完全に平坦なChroma Key背景で生成し、Alphaへ変換する。被写体に緑が少ない場合は`#00ff00`、緑を含む場合は`#ff00ff`を使う。

- 背景に影、Gradient、床、反射を描かない
- 被写体自身の陰影は残す
- Cast Shadowは別レイヤーとし、Sprite本体へ焼き込まない
- 四辺に10%以上の余白を置く
- Alpha変換後にCorner透明度、輪郭のFringe、被写体占有率を検査する

## 4. 車体合成

Playerは次の画像とAnchorから構成する。

- `vehicleBase`: 車体、標準バッテリー、接続Rail、前後輪を統合した本体
- `primaryWeapon`: 主武器
- `secondaryWeapon`: 副武器
- `module0..3`: Rear Rail 3枠とRoof Cradle 1枠へ実装するModule
- `muzzlePrimary`, `muzzleSecondary`: Muzzle Flash起点
- `wheelFront`, `wheelRear`: 任意の回転中心
- `shadow`: 地面影

車輪と装備のAnchorはSprite中央X・Ground Yを原点とする正規化座標で保持する。同じDefinition IDから画像パスとAnchor定義を解決する。ModuleはReward用画像を裸で重ねず、背面Connector、Cradle、前面Retainer、Boltで挟み込んで実装する。

Caravanの見た目は[ADR 0004](adr/0004-caravan-monster-visual-direction.md)に従う。主武器、副武器、最大4つのModuleを同時に読めるよう、Anchorの優先順位と占有範囲を定義する。

## 5. Monster素材

敵は車両SpriteではなくMonster Spriteとする。`basic`、`rusher`、`heavy`、`artillery`、`bomber`、Bossで体型を重複させない。

- 通常敵は左向きで生成する
- 目、口、角、甲羅、傘、果実など役割を示す部位を大きくする
- 旧文明のScrapは装飾または自然な装甲として少量だけ使う
- 武器を手に持つ兵士や操縦席のある車両にはしない
- Damage、Attack予兆、Elite VariantはTintだけでなく模様や発光部位でも示す

## 6. 描画とAnimation

- 横位置はSimulation座標を画面座標へ変換する
- 奥行きはレイヤー順だけで表現し、ゲームルールへ使わない
- 移動時は前後HubのMarkerを移動距離に比例して回転する。車体と車輪は一枚絵で接地固定し、一律の上下揺れや車体Pitchは使わない
- 加速・巡航・制動中は速度に応じて段階的な排気Smokeを表示する
- 発射時は武器を後方へ移動して反動を表現する
- Hitは短い白点滅と小VFX、Overheatは赤みとSmokeで表現する
- Explosionは`startup → peak → decay`の3〜6 frameとする
- Monsterは左向き専用素材を用意し、非対称部位の反転事故を避ける

## 7. Stage・VFX・UI

- Stageは遠景、中景、Road、前景植生へ分ける
- VFXはCore、Flash、Smoke、Debris、Dustを分離またはSprite Sheet化する
- React HUDは生成画像を一枚貼るのではなく、CSS Panel、Icon、Bar、Pipを組み合わせる
- 10戦進行、Threat、主副武器、Module 4枠を常時表示する
- 画面中央のMonsterとProjectileをUIで隠さない

## 8. 保管

- 生成MasterとPromptは`artifacts/g0/`以下へ保存する
- ゲームで直接読む最適化済み素材は`public/assets/`以下へ保存する
- Asset manifestへ生成元、生成日時、Prompt、Hash、採否を記録する
- 現在のG0画像は約2MBのため通常Gitで管理する
- Git LFSは未導入のため、Master総量が増える前に改めて導入可否を判断する
