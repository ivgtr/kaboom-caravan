# Kaboom Caravan 2D Animation実装計画

- Status: In Progress
- Version: 1.1
- Date: 2026-08-11
- Scope: Presentation only
- Related: [2D素材設計書](2D素材設計書.md)、[ADR 0003](adr/0003-2d-layered-presentation.md)、[ADR 0004](adr/0004-caravan-monster-visual-direction.md)

## 1. 目的

現在の全身Spriteへ一律の上下Sin波を加える表現を廃止し、重量、接地、武器反動、
Monsterの生態と攻撃意図が伝わる2D Animationへ移行する。

Animationはゲーム状態を変更しない。Simulation Eventと読み取り専用Snapshotから
Presentation Stateを作り、Canvas 2Dで再生する。

## 2. 現状の問題

- Caravan本体、車輪、サスペンションが一枚絵で、車輪を接地させたまま車体だけ動かせない
- 主武器、副武器、Moduleを含む全体へ同じ上下移動が加わり、重量物に見えない
- `performance.now()`のSin波が移動量や速度と無関係で、停止と移動の切り替えも唐突
- 全Monsterが種類やBehaviorに関係なく同系統の周期運動を行う
- Attack anticipation、Hit reaction、Death、Boss phase transitionが不足している
- Reward用の斜めEquipment Renderを戦闘画面にも使っており、車体の横視点と完全には一致しない
- Muzzle、Hit、Explosionは多層化済みだが、専用Animation Graphicをまだ使用していない

## 3. 採用方式

### Kawaii補正Lock

- 生物として読める丸いシルエットを最優先する
- 岩、瓦礫、遺跡、旧文明パーツは総面積の15%以下に制限する
- Heavyは瓦礫の山ではなく、滑らかな甲羅を持つ亀型Guardianにする
- Bossは城や石像ではなく、生物70%以上の大型Guardianにする
- 亀裂、錆、汚れ、現実的な石肌を使用しない
- 危険性は岩肌ではなく、Attack Pose、発光Core、重量、VFXで表現する

このLockは既存の`enm_*_v001`より優先する。v001は形状Referenceとして使わず、
Paletteと世界観の比較対象にだけ残す。

全面的なコマ送りAnimationではなく、次のハイブリッド方式を採用する。最初のRuntime統合では
同一2×2 Sheet内の`idle / move / anticipation / release`を状態で切り替え、形状とAnchorを
確定する。承認後、必要な部位だけRaster Rigへ分離する。

### Raster Rig

硬い部品を透明Rasterへ分離し、Anchorを中心に位置・回転・Scaleを動かす。

- Caravan chassis
- Front / Rear wheel
- Primary / Secondary weapon
- Module attachment
- Ground shadow
- Exhaust / heat vent
- Monsterの硬い甲羅、傘、果実、Boss coreなど

### Short Sprite Clip

シルエットそのものが変化するActionだけ、3〜6 frameの短いClipにする。

- Monster attack anticipation / release
- Rusher charge
- Bomber detonation anticipation
- Artillery spore launch
- Boss phase transition
- Destruction / disappearance
- Explosion、Muzzle、Hit、Smoke、Dust

AI画像で各frameを別々に生成すると形が揺れるため禁止する。1枚の横Stripとして生成するか、
採用済み基準Spriteを編集Targetにして全frameを同一Canvas上へ生成する。

## 4. Motion原則

1. 車輪、足、甲羅底面などのGround ContactはIdle中に上下させない
2. 動作は`anticipation → action → recovery`で構成する
3. 大きい武器ほど反動を大きく、復帰を遅くする
4. 常時動かすのは呼吸、排気、微細なSecondary Motionだけにする
5. Hitは移動方向と逆へ2〜5px押し、白Flash後に復帰する
6. 重要な攻撃予兆は色だけでなくPoseとScaleでも示す
7. Input／Eventから100ms以内に視覚反応を開始する
8. `prefers-reduced-motion`では揺れとSecondary Motionを弱めるが、攻撃予兆は残す

### Motion

- Idle: 車輪と影は固定。車体だけ0.5〜1pxの遅い呼吸、排気弁が小さく動く
- Move: 前後Hub Markerを同位相で回転し、速度に応じて排気Smokeを変える
- Brake / Reverse: Simulationの慣性とSmoke間隔で重量を示し、車体・接地軸は傾けない
- Fire: Weaponだけ先に後退し、0〜40ms遅れてChassisへ小反動が伝わる
- Heavy Fire: Shadowを一瞬横へ広げ、Suspensionを沈ませる
- Hit: ChassisとAttachmentを同方向へ押し、Weaponは少し遅れて追従する
- Overheat: 車体は接地固定。排気弁、赤熱Overlay、Smokeを段階的に強める

### Player Rig v003実装結果

- v002の`move`姿勢はPlayer移動に使用しない
- Idle車体を固定し、`veh_player_rig_parts_v003`は排煙だけに使用する
- 車輪と車体は地面へ固定し、武器だけへ反動を適用する
- 速度0.75以上で小・中・拡散Smokeを順に再生する
- Simulationへ速度を保持し、加速30、惰性減速18、逆入力制動42の慣性を追加する

### Player Chassis v004補正

- 車輪画像を完成車体の前面へ重ねるv003方式を廃止する
- Chassis、Fender、前後輪を一枚の完成Spriteとして描画する
- 動的に描くのはHub上の小さなCyan回転Markerだけに限定する
- 前後Hub中心はRuntime画像から測定し、同一Y軸へ固定する
- `debug=motion`で軸線、前後Center、Ground Contactを確認可能にする
- 車輪が車体へ焼き込まれたため、移動PitchでChassis自体を回転させない

### Player Chassis v005装備実装

- 旧デザインのCyan CellとPurple Power Boxを標準装備として車体へ統合する
- Battery、Clamp、Cable、Rear Railは一枚絵にし、走行中も相対位置を変えない
- 取得ModuleはRear Rail 3枠とRoof Cradle 1枠へ順に装着する
- Module本体の背後へConnectorとCradle、前面へRetainerとBoltを描き、貼付表示を禁止する
- Module画像は縦横比を維持し、装着Slotだけが位置・角度・Scaleを決定する

## 8. Asset生成仕様

- Style Reference: `artifacts/g0/style-reference/ref_style_001.png`
- Character Reference: 現在採用中の各`public/assets/world/*.png`
- Chroma Key: 原則`#ff00ff`、対象にMagentaがある場合のみ`#00ff00`
- Frame Master: 1 frameあたり1024〜1536px
- Strip: 4 frameなら4096×1024相当、全frameでCanvasとGround Lineを固定
- Safe Margin: 12%以上
- Frame間で固定するもの: 色、輪郭幅、光源、顔、装甲形状、被写体Scale、Ground Contact
- 変えてよいもの: 指定部位のPose、Squash、発光、Smoke、Debris
- Alpha化後にFringe、欠損、Bounds、Frame間の重心移動を検査する
- 32px／64px／実ゲーム表示でContact Sheetを確認する

生成物は`artifacts/animation/masters/`、Runtime素材は
`public/assets/animation/`へ保存し、Promptと採否を
`docs/assets/animation-manifest.md`へ記録する。

## 9. Runtime設計

### データ構造

```ts
interface AnimationClipDefinition {
  id: string;
  frames: readonly string[];
  framesPerSecond: number;
  loop: boolean;
  groundAnchor: readonly [number, number];
}

interface RigLayerDefinition {
  assetId: string;
  pivot: readonly [number, number];
  parentAnchor: string;
  drawOrder: number;
}

type MotionState =
  | 'idle'
  | 'move'
  | 'attack-anticipation'
  | 'attack-recovery'
  | 'hit'
  | 'overheat'
  | 'death';
```

Entity IDごとにPresentation専用の`MotionController`を持ち、Simulation tickではなく
補間済み位置、速度、Combat EventからStateを遷移させる。消滅したEntityのControllerは
Poolへ戻す。

### Event mapping

| Event / Snapshot        | Motion                                       |
| ----------------------- | -------------------------------------------- |
| Position差分            | Idle ↔ Move、Wheel回転、足運び               |
| `weapon-fired`          | Weapon recoil、Muzzle Clip、Chassis reaction |
| `projectile-hit`        | Target hit reaction、Hit Clip                |
| `enemy-attacked`        | Monster attack anticipation / recovery       |
| `enemy-killed`          | Death Clip、Explosion、Dust                  |
| `overheated` / `cooled` | Heat vent、Smoke、Tint transition            |
| `skill-activated`       | Chassis squat、後方Dust、Speed line          |
| `boss-phase-changed`    | Boss Phase Clip、Core Overlay                |

## 11. 自動検証

- Motion State遷移が同一Event列で再現可能
- Ground Anchorの画面上Y誤差がIdle時1px以内
- Wheel回転量が移動距離と同方向
- RecoilがWeaponごとの設定上限を超えない
- Attack予兆開始から攻撃Eventまでの順序が一致
- Clip frame参照、Asset ID、Anchorがすべて解決する
- Motionを有効化してもSimulationの固定Seed結果が変わらない
- 主要ViewportでSpriteとHUDが交差しない

## 12. 完了条件

- 停止中に車輪・足が地面から浮かない
- Caravanの重量、加速、停止、武器反動が視覚的に区別できる
- Monster 5種とBossが異なる移動・攻撃Motionを持つ
- 攻撃予兆を文字なしで理解できる
- Hit、Overheat、Deathの状態変化が100ms以内に伝わる
- 装備変更後もAnchor、反動、Muzzle位置が破綻しない
- 常時上下Sin波へ依存しない
- 生成Graphic、Prompt、採否、Runtime参照がRegistryへ記録されている
