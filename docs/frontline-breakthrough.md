# 前線突破の設計と確認方法

## 変えたいプレイ体験

既存の前後移動・武器の適正距離・熱管理・パリィを捨てず、危険を取った成功を「好きな局面で使える反撃の権利」に変える。単なる自動強化や追加武器ではなく、前進して獲得する／温存する／ここで使う、という短期と次戦にまたがる判断を作る。

満タンでも自動発動しない。敵が少ない時の火力投入、過熱と敵弾が重なった時の切り返し、次戦に向けた温存にはそれぞれ機会費用がある。押し戻しによって短射程武器の間合いから敵が離れるため、攻めに使う場合も前進が必要になる。

## ルールの境界

数値の定義は `src/game/simulation/breakthrough.ts` に集約。前線での命中は0.75秒に1回だけ評価し、散弾数・巻き込んだ敵の数・ダメージ量で無制限に稼げない。命中時の車両位置を見る。パリィは後方でも獲得できるが、同一ステップの複数成功は1回の加算にする。

発動処理は敵弾との衝突より先に解決する。敵弾消去をパリィ成功として扱わず、弾薬・エネルギー・耐久を無償補給しない。強化中は新しく飛んだ敵弾で被弾し、ゲージも再獲得できない。ボスの押し戻しは通常敵より小さい。未使用ゲージだけ次戦へ持ち越し、強化時間・命中加算待ち時間は持ち越さない。新しいランでは0から始める。

入力は押下を1回だけ次の固定ステップへ渡す。長押し・キーリピートで満タン到達時に暴発しない。一時停止・ウィンドウ離脱・メニューへの移行で未処理入力を破棄する。強化時間と描画演出は同じシミュレーション時間で進み、別の実時間タイマーは作らない。

## 手動確認

`npm ci` と `npm run dev` を実行し、通常の整備庫から開始する。前進して命中させるかパリィに成功するとゲージが増え、100%で `E` または「前線突破」を1回押すと発動する。弾薬が減ること、無敵ではないこと、未使用ゲージが報酬・ルート選択を挟んでも残ることを確認する。

素早い再現には開発用の `/?debug&breakthroughPreview=charging` を使う。94%・40m・敵ありで始まるため、Eを押したまま主武器を命中させても自動発動せず、Eを離して押し直すと発動することを確認できる。`/?debug&breakthroughPreview=ready` は100%・過熱状態で始まり、排熱と残り時間の停止／再開を確認できる。通常開始時にはこのプレビュー状態を使わない。

## 自動検証と残る判断

単体・結合テストは獲得条件、上限、発動順序、資源消費、ボス、戦闘間の持ち越し、入力破棄を検証する。既存の3シードの固定期待値は突破未使用時に維持し、使用する自動プレイでも全10戦のクリアと決定的なリプレイを検証する。

Chromiumでは通常開始、実際の命中による獲得、長押し、キーボード・タッチ操作、一時停止・離脱、4画面サイズを検証する。小型横画面では操作ボタンや上部HUDとの非重複に加え、パネルが車両のいるフィールド下部を隠さないことを検証する。CIの `combat-interaction-report` にレポートと撮影画像を保存する。

これらは操作と進行の成立を確認するテストであり、面白さや最適な数値の証明ではない。実プレイヤーによる検証では、獲得までの待ち時間、攻撃と防御の使い分け、短射程と長射程の獲得機会、スマートフォンでの視認性を重点的に見る。
